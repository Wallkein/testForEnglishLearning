Ответы на вопросы по теоретической части

1. Что такое строгий режим? Для чего он нужен?

Строгий режим в JavaScript включается строкой "use strict". Обычно ее пишут в начале файла или функции.

Он нужен для того, чтобы JavaScript вел себя строже и не пропускал некоторые ошибки. Например, без строгого режима можно случайно создать глобальную переменную, просто забыв написать let, const или var. В строгом режиме такой код сразу упадет с ошибкой.

Пример:

"use strict";
x = 10; // будет ошибка, потому что переменная x не объявлена

Также строгий режим запрещает некоторые устаревшие или опасные возможности языка. В современных ES-модулях и классах строгий режим включен автоматически.

2. В чем отличие var, let и const? Что лучше использовать?

var - старый способ объявления переменных. У него функциональная область видимости, а не блочная. Это часто приводит к неожиданному поведению, особенно в циклах и замыканиях. Еще var можно повторно объявлять в одной и той же области видимости.

let - современный способ объявить переменную, значение которой потом может измениться. У let блочная область видимости, то есть переменная существует только внутри блока { }.

const - тоже имеет блочную область видимости, но переменную нельзя переназначить после объявления. При этом если в const лежит объект или массив, менять внутренние свойства все равно можно.

Пример:

const user = { name: "Иван" };
user.name = "Петр"; // можно
// user = {}; // нельзя

На практике нужно использовать const по умолчанию. Если значение должно меняться, тогда let. var в современном коде лучше не использовать, если нет особой причины.

3. Операторы сравнения

Отличие == от === и != от !==

== сравнивает значения с приведением типов. То есть JavaScript может сам преобразовать строку в число, false в 0 и так далее.

=== сравнивает строго: сначала проверяет типы, потом значения. Если типы разные, результат сразу false.

То же самое с != и !==: первый вариант делает приведение типов, второй нет.

В обычном коде лучше использовать === и !==, потому что так меньше неожиданных результатов.

'01' == 1 и '01' === 1

'01' == 1 даст true. При нестрогом сравнении строка '01' приводится к числу 1.

'01' === 1 даст false, потому что слева строка, а справа число. Типы разные.

null === undefined и null == undefined

null === undefined даст false, потому что это разные типы.

null == undefined даст true. В JavaScript есть специальное правило: при нестрогом сравнении null и undefined равны друг другу.

null > 0, null == 0, null >= 0

Результат будет такой:

null > 0  // false
null == 0 // false
null >= 0 // true

Причина в том, что == и операторы сравнения вроде >, >= работают по разным правилам.

При null == 0 null не превращается в 0. Он равен только undefined и самому себе, поэтому результат false.

А при null >= 0 null приводится к числу. Number(null) - это 0. Поэтому 0 >= 0 дает true.

undefined > 0, undefined < 0, undefined == 0

Результат:

undefined > 0  // false
undefined < 0  // false
undefined == 0 // false

undefined при числовом сравнении превращается в NaN. Любое сравнение с NaN дает false. А при == значение undefined равно только null и самому себе, но не 0.

4. Можно ли сохранить функцию в переменную?

Так как в JavaScript функция - это значение. Ее можно сохранить в переменную, передать в другую функцию или вернуть из функции.

Пример:

const sayHello = function(name) {
  return "Привет, " + name;
};

const sayHelloArrow = (name) => "Привет, " + name;

console.log(sayHello("Иван"));

Именно поэтому в JavaScript часто используются колбэки, обработчики событий, map, filter и другие функции, которые принимают функцию как аргумент.

5. Функция с колбэками для подтверждения действия

function confirmAction(question, onConfirm, onCancel) {
  const answer = prompt(question + " Напишите да или нет");

  if (answer !== null && answer.trim().toLowerCase() === "да") {
    onConfirm();
  } else {
    onCancel();
  }
}

Пример использования:

confirmAction(
  "Вы точно хотите удалить выбранный элемент?",
  () => console.log("Элемент удален"),
  () => console.log("Удаление отменено")
);

Лучше использовать confirm(), потому что он сразу возвращает true или false.

6. Объекты, методы объектов и this

this - это контекст вызова функции. Это объект, от имени которого вызвали функцию.

Пример:

const user = {
  name: "Анна",
  sayName() {
    console.log(this.name);
  }
};

user.sayName(); // Анна

Здесь this указывает на объект user.

Потеря this происходит, когда метод отрывают от объекта:

const user = {
  name: "Анна",
  sayName() {
    console.log(this.name);
  }
};

const fn = user.sayName;
fn(); // this потерян

То же самое может случиться, если передать метод как колбэк:

setTimeout(user.sayName, 1000);

Решить проблему можно через bind:

const fn = user.sayName.bind(user);
fn(); // Анна

Или через стрелочную функцию:

setTimeout(() => user.sayName(), 1000);

Стрелочные функции не имеют собственного this. Они берут this из внешней области. Поэтому в классах и обработчиках они часто помогают избежать потери контекста.

7. setTimeout и setInterval

setTimeout выполняет функцию один раз через указанное время.

const timerId = setTimeout(() => {
  console.log("Прошла 1 секунда");
}, 1000);

clearTimeout(timerId);

setInterval выполняет функцию много раз через заданный интервал.

const intervalId = setInterval(() => {
  console.log("Каждую секунду");
}, 1000);

clearInterval(intervalId);

Главное отличие setInterval от рекурсивного setTimeout в том, что setInterval запускает функцию по расписанию, eсли функция выполняется долго, вызовы могут начать накапливаться.

Рекурсивный setTimeout планирует следующий запуск только после выполнения текущего:

function tick() {
  console.log("Запрос к серверу");
  setTimeout(tick, 1000);
}

setTimeout(tick, 1000);

Такой вариант часто удобнее для polling-запросов, потому что можно контролировать паузу, обрабатывать ошибки и менять задержку.

8. Что такое TypeScript? Для чего он нужен? Чем отличается от JavaScript?

TypeScript - это надстройка над JavaScript, которая добавляет статическую типизацию. Код на TypeScript потом компилируется в обычный JavaScript.

Главная польза TypeScript в том, что он помогает находить ошибки еще до запуска приложения. Например, если функция ждет число, а мы передаем строку, TypeScript подсветит ошибку заранее.

Также типы улучшают автодополнение в редакторе, помогают читать код и безопаснее делать рефакторинг.

От JavaScript TypeScript отличается тем, что в нем можно описывать типы переменных, аргументов функций, объектов, ответов API и так далее. Но в браузере в итоге выполняется не TypeScript, а скомпилированный JavaScript.

9. Базовые типы TypeScript

Основные типы:

string - строка:

let name: string = "Иван";

number - число:

let age: number = 25;

boolean - true или false:

let isActive: boolean = true;

array - массив:

let numbers: number[] = [1, 2, 3];
let names: Array<string> = ["Анна", "Иван"];

tuple - кортеж, массив фиксированной структуры:

let user: [string, number] = ["Иван", 25];

null и undefined - отдельные значения.

any - отключает проверку типов. Лучше использовать редко, потому что теряется смысл TypeScript.

unknown - похож на any, но безопаснее. Перед использованием нужно проверить тип.

void - обычно означает, что функция ничего не возвращает:

function log(message: string): void {
  console.log(message);
}

never - тип для ситуаций, когда функция никогда нормально не завершится, например всегда выбрасывает ошибку.

Также часто используются union-типы:

let id: string | number;
id = "abc";
id = 123;

10. Generics в TypeScript

Generics - это обобщенные типы. Они позволяют написать функцию или тип один раз, но использовать его с разными типами данных.

Простой пример:

function identity<T>(value: T): T {
  return value;
}

const a = identity<string>("hello");
const b = identity<number>(123);

Здесь T - это тип, который подставится при вызове функции.

Еще пример - ответ API:

interface ApiResponse<T> {
  data: T;
  error: string | null;
}

const usersResponse: ApiResponse<string[]> = {
  data: ["Иван", "Анна"],
  error: null
};

Generics удобны тем, что мы не теряем информацию о типах. Если бы вместо T использовали any, TypeScript не смог бы нормально проверять код.

11. type и interface в TypeScript. В чем отличие?

И type, и interface можно использовать, чтобы описывать форму объекта.

interface User {
  name: string;
  age: number;
}

type UserType = {
  name: string;
  age: number;
};

Во многих случаях они взаимозаменяемы. Но отличия есть.

interface можно расширять через extends:

interface Admin extends User {
  role: string;
}

type чаще используют для union-типов, литеральных типов, кортежей и более сложных комбинаций:

type Id = string | number;
type Status = "loading" | "success" | "error";

Еще interface можно переоткрывать, если объявить interface с одним и тем же именем несколько раз, TypeScript объединит их. С type так нельзя.

На практике лучше использовать interface для описания объектов и контрактов, а type - для union-типов и сложных комбинаций.

12. Как сделать свойства интерфейса необязательными?

Чтобы сделать отдельное свойство необязательным, после имени ставится знак ?.

interface User {
  name: string;
  age?: number;
  email?: string;
}

Теперь объект может быть без age и email:

const user: User = {
  name: "Иван"
};

Чтобы сделать все свойства необязательными, можно использовать Partial<T>.

interface Profile {
  firstName: string;
  lastName: string;
  age: number;
}

type PartialProfile = Partial<Profile>;

Теперь все поля в PartialProfile необязательные.

13. Для чего нужен Omit в TypeScript?

Omit нужен, чтобы взять существующий тип и убрать из него одно или несколько свойств.

Пример:

interface User {
  id: number;
  name: string;
  password: string;
}

type PublicUser = Omit<User, "password">;

В PublicUser будут id и name, но не будет password.

Это можно применить, например, когда есть полный тип пользователя, 
но на клиент или в публичный объект нельзя отдавать пароль. Еще часто Omit используют для формы создания сущности, 
где id еще нет, потому что его создаст сервер.

Пример:

type CreateUserDto = Omit<User, "id">;

14. Можно ли в TypeScript перегрузить функцию?

В TypeScript можно описать несколько вариантов вызова функции, а реализацию написать одну.

Пример:

function format(value: number): string;
function format(value: string): string;
function format(value: number | string): string {
  if (typeof value === "number") {
    return value.toFixed(2);
  }

  return value.trim();
}

format(10);       // ok
format(" text "); // ok
// format(true);  // ошибка

Перегрузка полезна, когда функция может принимать разные типы аргументов, но для каждого варианта хочется сохранить понятные подсказки и строгую проверку типов.

Иногда вместо перегрузки достаточно union-типа, например string | number. Но если вариантов много или возвращаемый тип зависит от входных аргументов, перегрузки могут быть удобнее.
